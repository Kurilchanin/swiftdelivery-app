2. Service Description

SwiftDelivery is a decentralised marketplace that connects Clients (people who need a parcel delivered) with Couriers (people willing to deliver it). Order logic and payments are handled by smart contracts on the TON blockchain. The platform does not act as a courier, does not participate in physical delivery, and does not guarantee delivery outcomes.

3. User Roles

Client — creates a delivery order, specifies the destination city, an optional origin place, a parcel description, and the delivery time (1 to 14 days), locks the reward in a smart contract, and confirms receipt by showing their delivery code to the Courier. A Telegram @username is required to create an order — it is visible to Couriers who open the order, so they can ask questions before accepting.

Courier — accepts an open order, performs the delivery, and receives the reward by scanning the Client's delivery code upon handover. A Telegram @username is required to accept an order — it is shared with the Client upon acceptance.

One Telegram account may act as both Client and Courier in different orders.

4. Payments and Fees

The delivery reward is paid in USDT, with a minimum of $10. The Client transfers the reward directly in USDT when creating the order; it is held by the order's own USDT wallet until it is released to the Courier or returned to the Client. Service fees and blockchain network fees are paid separately from the reward, in GRAM — the name the Service uses for the native coin of the TON blockchain.

The Service charges flat service fees, paid to the smart contract. Each service fee already includes all blockchain network fees of that action; nothing is charged on top:

Create fee — 0.1 GRAM, paid by the Client together with the reward when creating an order. Non-refundable under any circumstances. The reward itself is returned to the Client if the order is cancelled or expires.

Accept fee — 0.1 GRAM, paid by the Courier when accepting an order. It is not a stake or deposit: it stays with the platform and is not returned, whether the delivery succeeds or not.

Cancel fee — 0.3 GRAM, paid by the Client when cancelling an open order, on top of the create fee already paid. Non-refundable.

Release fee — 0.2 GRAM, paid by the Courier when giving up an accepted order, on top of the accept fee already paid. Non-refundable.

Confirming a delivery and reclaiming an expired order have no service fee: the caller pays only a small network fee, which the app measures before you sign. Cancelling an order whose reward has not yet arrived (Funding) has no service fee either.

Because transactions are executed on a public blockchain they are irreversible. Please verify all order details before confirming a transaction.

5. Order Process and Delivery Code

An order may be in one of the following states: Funding (created, the reward is on its way to the order, usually a few seconds), Open, Accepted, Completed, Cancelled, or Expired.

Delivery confirmation: when creating an order the Client receives a private delivery code (shown as a QR code). Delivery is confirmed when the Courier scans this code — scanning it pays the Courier the reward; there is no separate confirmation step. The Client must show the code only when the parcel is in their hands. The code is stored on the Client's device and backed up to their Telegram account's cloud storage. If the code is lost, the Courier cannot be paid, and the Client can reclaim the reward after the deadline.

Deadline: the Client chooses the delivery time, from 1 to 14 days, when creating the order. After a Courier accepts the order, they have that many days to complete the delivery. If delivery has not been confirmed before the deadline, only the Client may reclaim the order via the smart contract. In that case the reward is returned to the Client; the Courier receives nothing.

Cancellation: the Client may cancel an order only while it is in the Open state (before any Courier accepts it). Once a Courier has accepted, the Client cannot cancel — the Courier must give the order up first, which returns it to Open, after which the Client may cancel. On cancellation the full reward is returned to the Client; the create fee and the cancel fee remain with the platform.

Courier release: a Courier who has accepted an order may give it up at any time before delivery is confirmed, paying the release fee. The order returns to Open and the reward remains locked in the contract for the next courier.

6. Referral Program

The app may be opened through a referral link that carries a partner's TON wallet address. The first referral link a user opens stays with their account for good; a later link does not replace it. Every order the user creates records that address on-chain, and the smart contract automatically pays that address half of the accumulated service fees when the order settles. This does not change the fees or the reward paid by the users of the order.
